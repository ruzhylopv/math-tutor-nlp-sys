# Plan: M7 app (approved 2026-10-27)

Scope: the Streamlit chat only. No report, no demo video, no test-split run (those stay open in M7).
Roadmap: `docs/plans/design/2026-10-25-roadmap.md`. M6 is merged.

## Decisions (from the developer)
- The sidebar shows the current hint level and hints used, plus the learner profile.
- "New chat" starts a new `thread_id` for the same name and does not touch the learner profile. The app reads the
  profile only through `get_profile`. All chats belong to one person.

## Defaults (not objected to)
- Chat history shown comes from the checkpoint, not from a second store in `st.session_state`. Rejected: a separate UI
  history (it could drift from the graph state).
- No new dependencies (Streamlit is already declared).
- Checkpointer path from an optional `CHECKPOINT_DB_PATH` (default `data/checkpoints.db`). Rejected: sharing the
  `LEARNER_DB_PATH` file (two schemas in one file).
- No eval script: the app is not a node. The scenario replay already covers behaviour.

## Files (one PR, one concern)
1. `src/tutor/ui.py`: `Tutor` (graph + checkpointer), `send` (one `invoke` via `new_turn`, returns a `TurnView` with
   reply, hint level, visited nodes or a friendly error), `latest_chat`, `load_history`, `sidebar_info`.
2. `app.py`: name field, chat bubbles, new-chat button, sidebar, node-visited toggle, setup message on `ConfigError`.
3. `src/tutor/config.py` and `.env.example`: `CHECKPOINT_DB_PATH`.
4. `tests/test_ui.py`, `tests/test_app.py` (`streamlit.testing.v1.AppTest`), model mocked, no network.
5. README "Run the app", `docs/decisions.md`, `docs/crisp_dm_log.md`.

Done check: `uv run ruff check . && uv run mypy && uv run pytest -q`, then the real app driven on a few turns.
